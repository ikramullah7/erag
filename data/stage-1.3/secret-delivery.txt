# Payments secret delivery RB-SEC-047

Owner: Platform Secrets | Dataset: stage-1.3-v1 | Status: synthetic training fixture

## Mount contract

SecretProviderClass payments-runtime-secrets mounts the database credential at /mnt/secrets-store/db-password. The mount uses workload identity rather than an embedded credential in the pod manifest. The configured secret rotation polling interval is 2 minutes. A polling interval does not establish the age or value of the currently mounted secret.

## Application reload

The payments application must reopen the mounted credential file after rotation; an already-open file handle can retain old content. Verify application connection recovery separately from a successful secret mount. Do not log the file contents or copy the database password into incident tickets. Platform Secrets owns the mount configuration; application teams own reload behavior.

## Failure isolation

For mount failures, check the service account subject, vault permissions and private DNS before restarting pods. This runbook contains no actual database password value, latest mount success timestamp or current secret version. The documented file path is not itself a credential value.
